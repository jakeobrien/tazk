Code review: weak dependency validation (self-dependency, unvalidated target IDs, related_to reported as cycles)

Where: src/storage.rs add_dependency, build_new_issue_no_lock, validate_dependency_exists (~line 1450), detect_dependency_cycles / find_cycles_dfs (~line 1768).

Problems (verified):
- `tz dep add X --target X` is accepted; with blocked_by, X can never become ready.
- The library does not validate dependency target IDs (only the CLI normalizes them); validate_dependency_exists swallows the IssueId parse error via unwrap_or(false) and just warns.
- `tz dep cycles` follows every dependency type, so two issues with mutual related_to links are reported as a cycle.

Suggested fix: reject self-dependencies; IssueId::parse the target in Storage; restrict cycle detection to directional types (blocked_by, child_of, maybe tracks).
