Code review: Storage::update_issue takes a stringly-typed HashMap and silently ignores unknown keys

Where: src/storage.rs update_issue and apply_issue_updates (~line 4434).

Problem: updates are HashMap<String, String>. Unknown keys fall through `_ => {}` silently (a typo is a no-op), values are re-parsed from strings, and the "issue_type" key (~line 4480) changes the type without re-checking role or section rules (validation runs against the old type). No CLI path sets "issue_type" today, but the API is public.

Suggested fix: replace with a typed struct, e.g. IssueUpdate { title: Option<String>, priority: Option<i32>, role: Option<Option<Role>>, effort: Option<Option<u8>>, ... }; validate rules against the post-update type; drop or properly validate issue_type changes.
