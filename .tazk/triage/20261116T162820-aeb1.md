Code review: unparseable closed_at is silently dropped; dead timestamp fallback formats

Where: src/format.rs markdown_to_issue (~line 334) and parse_timestamp (~line 452).

Problems:
- closed_at uses `.and_then(|s| parse_timestamp(s).ok())`, so a bad value is silently discarded and the next write removes closed_at from a closed issue (verified: `closed_at: yesterday` on a closed issue; after `tz label add` the field was gone). created_at/updated_at fail loudly instead.
- The fallback formats "%Y-%m-%dT%H:%M:%SZ" and "%Y-%m-%d %H:%M:%S" can never succeed: DateTime::parse_from_str requires an offset (verified: `created_at: 2025-01-01 00:00:00` fails). "%Y-%m-%dT%H:%M:%S%:z" is already covered by RFC 3339.

Suggested fix: propagate the closed_at parse error like the other timestamps; remove the dead formats or parse them as NaiveDateTime and assume UTC if they are meant to be supported.
