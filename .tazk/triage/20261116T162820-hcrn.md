Code review: creating an issue writes the file in place (not atomically)

Where: src/storage.rs write_new_issue_to_path.

Problem: it uses OpenOptions::create_new + write_all with no fsync, so a crash or full disk can leave a truncated issue file. Because the strict loader fails on any bad file, one truncated file breaks list/ready/stats for the whole database.

Suggested fix: write to a temp file in the same directory, fsync, then tempfile's persist_noclobber (hard link, fails if the target exists). That is atomic and never overwrites, keeping the current guarantee.
