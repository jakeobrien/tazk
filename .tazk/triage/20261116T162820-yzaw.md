Code review: multi-issue commands are not atomic

Where: src/main.rs Update, Close, Claim, Block/Defer arms; src/storage.rs repair_references (~line 1399).

Problems:
- `tz update a b c ...` writes issue by issue; a failure on c leaves a and b changed. The same applies to close, claim, block and defer (reopen does a precheck, the others don't).
- update performs three or more separate locked writes per issue (fields, then set_labels, then each add/remove label), each bumping updated_at.
- repair_references writes each repaired issue separately, so a failure part way leaves a partial repair.

Suggested fix: validate everything first, then stage all writes in one FileTransaction (already used for renames, triage and migrations); apply all field and label changes to an issue in a single write.
