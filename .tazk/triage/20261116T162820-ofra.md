Code review: tz sync writes unvalidated JSONL records into Markdown, breaking the whole database

Where: src/sync.rs, load_jsonl_issues and SyncEngine::apply_to_path.

Problem: JSONL records are deserialized straight into Issue and written with issue_to_markdown, bypassing everything markdown_to_issue enforces (effort range 1-5, section rules per type, dependency ID format, etc.).

Repro (verified): a JSONL line with "effort":9, then `tz sync --jsonl bad.jsonl --direction to-markdown` succeeds ("Created in markdown: 1"); afterwards `tz list` fails for the whole database with "Invalid effort: '9'".

Suggested fix: validate each JSONL record before staging the write, e.g. round-trip it through issue_to_markdown + markdown_to_issue (and IssueId::parse each dependency key), and reject or report invalid records.
