Per-type body templates and validation for `epic`, `spec` and `gate`

Every issue type currently shares one body format: Description / Design / Acceptance Criteria / Notes. The solo-directed-agents workflow (docs/workflows/solo-directed-agents.md) uses these types with different lifecycles, and each would be better served by its own shape:

- work types (`task`, `bug`, `feature`, `chore`): unchanged.
- `epic`: Description + Acceptance Criteria (default: all children closed). No Design.
- `spec`: a free-form body (any headings, possibly long, with numbered sections that tickets refer to) + Notes. The four standard sections fit poorly.
- `gate`: a placeholder blocker with no work attached, closed when an outside condition becomes true (upstream release, event, decision). Sections: Condition (what must happen) + How to check. `role` says who checks.

Things to decide: what `create`/`update` flags exist per type; whether a spec body is opaque to section parsing (so `## Headings` inside it don't collide with the issue's sections); how `--field` names map; what the TUI detail view shows; whether validation is a hard error or a warning (`--tz-validation`). Related: the triage item that makes `role` optional for epic/spec.

Until then the workflow doc describes these as conventions.
