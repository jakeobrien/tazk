Code review: duplicated read-modify-write boilerplate in Storage methods

Where: src/storage.rs: update_issue, add_label, remove_label, set_labels, search_replace_issue, append_to_issue, claim_issue, release_issue, set_hold, close_issue, reopen_issue, add_dependency, remove_dependency (about 15 methods).

Problem: each repeats "lock for write -> existing_issue_path -> read -> markdown_to_issue -> mutate -> updated_at = now -> write_issue_to_path". Changes to the pattern (validation, transactions, no-op detection) must be repeated everywhere; e.g. add_label and remove_label bump updated_at even when nothing changed.

Suggested fix: add a helper such as `fn modify_issue(&self, id: &str, f: impl FnOnce(&mut Issue) -> Result<()>) -> Result<Issue>` that also skips the write when nothing changed.
