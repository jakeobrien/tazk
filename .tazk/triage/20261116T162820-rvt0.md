Code review: tz sync brings back issues that were deleted by hand

Where: src/sync.rs SyncEngine::analyze_ref.

Problem: sync has no record of deletions (no tombstones or base snapshot). An issue whose Markdown file was removed by hand is classified jsonl_only and recreated from issues.jsonl on the next `tz sync`. Sync also compares file mtimes with updated_at, and git checkout/clone resets mtimes, which can pick the wrong winner.

Suggested fix: decide and document intended semantics; e.g. keep a last-synced snapshot (three-way sync) so deletions and edits can be told apart, or document that deleting requires removing the JSONL record too.
