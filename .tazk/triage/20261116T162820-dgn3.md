Code review: dependency tree and cycle output order is nondeterministic

Where: src/storage.rs build_tree_node (~line 1744) and detect_dependency_cycles.

Problem: both iterate Issue::depends_on / the issues map, which are HashMaps, so `tz dep tree` child order, the order of reported cycles, and which rotation of a cycle is printed vary between runs. Bad for diffs, scripts and tests.

Suggested fix: iterate in sorted ID order (collect and sort keys, or use BTreeMap); normalize each cycle to start at its smallest ID.
