Code review: tz blocked and tz stats ignore an issue's own blocked status

Where: src/storage.rs get_blocked (~line 1976), get_stats, is_blocked_with_ancestors / inherited_blockers.

Problem (verified): inherited_blockers counts an ancestor's `blocked` status, but an issue's own `blocked` status is not considered. After `tz block <epic>`, `tz blocked` lists only the epic's child ("blocked status, inherited") and not the epic itself; stats "Blocked" counts the child only. Stats also mixes dimensions: Open/In Progress/Closed are statuses while Blocked is dependency-blocked, so the numbers don't add up to Total and deferred issues aren't shown.

Suggested fix: decide the intended meaning; most likely include own status == blocked in get_blocked and the stats count, and show status counts and dependency-blocked counts separately.
