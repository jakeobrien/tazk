Code review: files written via atomic_write are created with 0600 permissions

Where: src/transaction.rs atomic_write_with_mtime (~line 31).

Problem: tempfile creates its temp file with mode 0600; permissions are only copied when the destination already exists. New files therefore end up 0600 instead of respecting the umask: renamed/renumbered issues, triage items, comment files, migrated and synced issues (verified: after `tz renumber` the issue file was -rw-------; triage items too). Files from `tz create` are 0644 because that path uses OpenOptions.

Suggested fix: when the destination does not exist, set permissions on the temp file to 0666 & !umask (e.g. tempfile::Builder::permissions, or create with OpenOptions and the default mode).
