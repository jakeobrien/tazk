Code review: Storage::open writes files without holding the lock

Where: src/storage.rs Storage::open.

Problem: every command (including read-only ones such as list and show) runs Storage::open, which creates directories, may create config.yaml, merges and deletes config-tazk.yaml (merge_legacy_tazk_config), and appends to .gitignore, all without the database lock. Concurrent commands can race on these writes (e.g. duplicate .gitignore lines, or a lost legacy-config merge).

Suggested fix: do the bootstrap writes under the lock, or only when something actually needs creating (check first, then lock and re-check).
