Code review: tz config set / unset accept invalid values and can break the database

Where: src/main.rs ConfigCommands::Set/Unset (~line 2832); src/storage.rs set_config_value, use_hash_ids (~line 489), issue_storage_layout.

Problems (verified):
- `tz config set issue-storage-layout bogus` succeeds; afterwards `tz show` / `tz create` fail with "Invalid issue-storage-layout" until config.yaml is fixed by hand.
- `tz config set tz-hash-ids yes` succeeds but is silently read as false (only the exact string "true" counts); the next `tz create` produced `tz-1` in a store that was using hash IDs.
- `tz config unset KEY` writes `KEY: ''` instead of removing the key; for issue-storage-layout that is an invalid value.

Suggested fix: validate known keys on set (parse the bool / layout), reject or warn on unknown keys, and make unset delete the key.
