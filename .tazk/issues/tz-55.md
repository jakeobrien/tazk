# Description

Implements tz-51 §4 and §5.3: `tz update` enforces the per-type section rule added in tz-54, checking only the sections the command changes, after applying the change.

Context:
- Reuse the rule and check helper from tz-54 (`src/types.rs`).
- Call sites, all in `src/storage.rs`, each checking the section's new value before writing the file:
  - `apply_issue_updates`: check only the body keys present in `updates` (`description`, `design`, `acceptance_criteria`, `notes`), like the role check already there;
  - `search_replace_issue`;
  - `append_to_issue`.
- Issues that break the rule must keep working for every command that doesn't change the offending section (same idea as tz-49's handling of old roles). `reopen` appends to Notes, which is optional on every type, so it is unaffected.
- With several IDs (`tz update a b c ...`), each issue is checked against its own type. The first failure stops the command, with the same partial-write behavior as other update errors today.

# Acceptance Criteria

- `tz update` fails when a change would leave a forbidden section non-empty or a required section empty, through: `-d`/`--description`, `--description-file`, `--design`, `--acceptance`, `--notes`; `--search`/`--replace` (with and without `--replace-all`) on any body `--field`; and `--append` on any body `--field`. The file is left untouched when it fails.
- Clearing a forbidden section (e.g. `--design ""`) succeeds.
- Only sections the command changes are checked: `--field title` and non-body flags are never checked.
- Issues that already break the rules still load, accept unrelated updates, `close` and `reopen`. Tests cover an epic with Design, a spec with Acceptance Criteria, and a gate with empty Acceptance Criteria (written to disk directly, bypassing the checks).
- Error messages follow tz-51 §5.4. When the failure is about an existing forbidden section, the message mentions that clearing it is allowed.
- Storage tests and `tests/body_sections.sh` cover each update mode on each non-work type.
- `make validate` passes.
