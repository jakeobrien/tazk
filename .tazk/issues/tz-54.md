# Description

Implements tz-51 §3, §5.1, §5.2, §5.4 and §8 for the commands that create issues. `create` and `triage promote` check every section, because every section is new (tz-51 §4). Updates are tz-55.

Context:
- Put the rule next to `IssueType::ensure_role_allowed` in `src/types.rs`, e.g. `IssueType::section_rule(EditField) -> SectionRule { Optional, Required, Forbidden }` plus a check helper that tz-55 will reuse. `EditField::Title` is always Optional. "Empty" means whitespace only (tz-51 §3).
- Enforce it in `Storage::build_new_issue_no_lock` (`src/storage.rs`), which both `create_issue` and `promote_triage_items` (`src/storage/triage.rs`) go through, so nothing is written on error. Apply the epic default Acceptance Criteria there too. The CLI handler may reject earlier, but storage is the authority.
- `triage promote` defaults the description to the items' text, so promoted specs and gates usually have one already. A gate still needs `--acceptance`.
- Things that will break and need updating:
  - `tests/role.sh` creates and promotes specs and gates without a description or `--acceptance`;
  - `tests/triage.sh` (around line 189) creates a spec with no description;
  - `src/action_generator.rs` (`generate_create` and the `TazkAction::Create` runner) gives specs and gates a description only half the time and never passes `--acceptance`;
  - the `create_typed` test helper in `src/storage.rs` passes an empty description.
- Follow the layout of `tests/role.sh` for the new `tests/body_sections.sh` (`tests/*.sh` are picked up by `tests/e2e_tests.rs` automatically).

# Acceptance Criteria

- The per-type section rule from tz-51 §3 lives in `src/types.rs`, using exhaustive `match`es with no wildcard arm; unit tests cover all 7 types × 4 sections.
- `tz create` and `tz triage promote` reject: non-empty `--design` on an epic, spec or gate; non-empty `--acceptance` on a spec; an empty or whitespace-only Description on a spec or gate; a gate without non-empty `--acceptance`. Error messages follow tz-51 §5.4, and nothing is written when a command is rejected.
- An epic created without `--acceptance` (or with an empty one) gets `- All child issues closed.`; an explicit `--acceptance` replaces that default.
- Work types (`task`, `bug`, `feature`, `chore`) behave exactly as before.
- Existing tests that now break are fixed by adding the missing text: `tests/role.sh`, `tests/triage.sh`, the `create_typed` helper in `src/storage.rs`, and `src/action_generator.rs`.
- New storage tests and a new `tests/body_sections.sh` cover each case above, for both `create` and `triage promote`.
- `make validate` passes.
