# Description

Make the canonical ID format of tz-39 §3 the only valid one, and use it to classify IDs exactly (§10). Also removes `tz create --id` (§6).

# Design

- `IssueId::parse` (src/paths.rs) validates `tz-` + (`[1-9][0-9]*` | `[0-9a-z]*[a-z][0-9a-z]*`). Expose helpers to tell numeric from hash (e.g. `IssueId::kind()` or `numeric_suffix() -> Option<u32>`) and use them instead of ad hoc `rsplit_once('-')` + `parse::<u32>()`.
- Move the portable-filename check (Windows device names, reserved characters, etc.) to a separate type (e.g. `PortableName`) and use it in `src/storage/triage.rs` for triage names. `IssueId` no longer needs it, because the strict pattern can't produce those names.
- Issue or comment files whose names don't match the format are invalid issues, reported under `--tz-validation` like other invalid files.
- `migrate --to numeric`: classify IDs by pattern. Delete `find_max_numeric_id_before_gap` and its warning output.
- `sharded_relative_path`, `numeric_id_suffix`/`compare_for_list`, `get_next_number`, migrate/repack: use the shared helpers.
- Remove `tz create --id` and `CreateIssueParams.id` (or the equivalent). Imports (`sync`/JSONL) require canonical IDs; anything else is an error for that record.
- `tests/regressions.rs` `unsafe_ids_…`: keep the coverage, but expect rejection by the format check (via the remaining entry points: import, and `rename` until tz-47 replaces it).

# Acceptance Criteria

- Unit tests for `IssueId::parse`: accepts `tz-1`, `tz-42`, `tz-a1b`, `tz-0k3x`; rejects `tz-0`, `tz-01`, `TZ-1` (stored IDs are lowercase), `tz-`, `tz-a-b`, `x-1`, `1`, `../x`, `con`.
- An `issues/` file named outside the format is reported as invalid (error by default, warning or skipped under the other `--tz-validation` modes) and doesn't crash `list`.
- Triage names still use the portable-filename check, and the existing triage tests pass.
- `rg find_max_numeric_id_before_gap src` finds nothing. `migrate --to numeric` on a mixed store renumbers exactly the hash IDs.
- `tz create --id` is unknown to clap; USAGE no longer mentions it.
- JSONL import rejects records with non-canonical IDs, with an error naming the record.
- `make validate` passes.
