# Description

Accept the bare suffix for every issue ID argument (tz-39 §4): `tz show 12`, `tz close a1b`, `--parent 3`, `--deps blocked_by:4,5`. Today only `tz show` expands, and only for numbers.

# Design

- One parser in the ID module: lowercase; if it matches the full format, keep it; else if it matches the suffix grammar, prepend the prefix constant; else fail with the §4 message. No store access.
- Wire it as a clap `value_parser` (or a single normalization pass) on every ID-taking argument listed in §4, including comma-separated values (`list --id`, `ready --id`) and the ID part of each `--deps` entry, after the type is split off. Remove the ad hoc expansion in `Commands::Show`.
- Not for triage item names. Not for IDs read from files.
- Output keeps printing full IDs.
- Help text: replace "supports shorthand: \"14\" expands to \"prefix-14\"" style comments with one consistent phrasing.

# Acceptance Criteria

- Unit tests for the parser: `12` -> `tz-12`, `tz-12` unchanged, `TZ-12` -> `tz-12`, `a1b` -> `tz-a1b`, `A1B` -> `tz-a1b`; `0`, `01`, `tz-`, `x-1`, `a-b`, `` (empty) rejected with the §4 message.
- Shell/e2e tests show shorthand working for at least: `show`, `update`, `close`, `claim`, `dep add` (both IDs), `dep tree`, `comments add`, `create --parent` and `--deps blocked_by:N,M`, `list --id N,M`, `ready --parent`, `triage promote --parent`, `triage attach --to`.
- Triage item names are unaffected (`tz triage show <name>` still works).
- USAGE documents the shorthand once, in the ID section.
- `make validate` passes.
